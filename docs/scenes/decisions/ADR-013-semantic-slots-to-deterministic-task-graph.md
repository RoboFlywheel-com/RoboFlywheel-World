# ADR-013：语义槽位交给模型，动作状态图由确定性构造器生成

- 状态：**accepted**（2026-10-01，SPEC-018 在线验收失败后的实现决定）
- 范围：G1 首版同层两房、单机器人、刚体取放；不改变 SPEC-017 图契约。

## Context

G1 让模型直接写完整图，包括节点、边、三段动作的前后态和验证义务。
确定性校验器拒绝无效候选，但一个错误引用或状态效果就使整次在线请求失败。

## Evidence

2026-10-01 的在线新目录 `_01`–`_07` 中没有一次有效图。较快且可用的模型服务
在 `_05`–`_07` 均于约 31–45 秒返回候选；补充缺口码后，`_06` 与 `_07`
连续以 `TASK_EFFECT_INVALID` 被拒，后一轮已明确提示 PICK/NAVIGATE/PLACE 的状态变化。
原始模型回复未落盘；可复核的失败码、请求数和耗时见 PLAN-018。

## Options

1. 继续要求模型写完整图，通过更长提示、更多 token 或重复请求碰运气。
2. 收到完整图后自动修补状态效果或悬空引用。
3. 模型只给任务语义槽位，确定性构造器据此生成图结构与状态代数（采用）。

## Decision

首版在线模型输出一份受限的两房取放语义提案：来源房间、目标房间、
共享门户、待取资产、来源支撑面、目标支撑面以及各自的用户来源/推断理由。
工具验证槽位完整、ID 唯一、能力兼容和歧义声明后，确定性构造三阶段任务图、
初态、效果、终态及 `not_run` 验证义务。模型不得提供已建几何或执行通过声明。
已有完整图 replay 继续作为图契约的兼容输入；无论哪种提案，编排器仍在
`ToolRequest/ToolResult` 边界重校验图和版本。首版只覆盖 SPEC-018 的取放切片；
其他动作具名拒绝，不猜测多步计划。

## Rationale

房间、物体和支撑面的语义来自用户任务，需要模型理解。取放状态代数、ID 引用、
义务列表是契约规定的机械规则，交由代码生成后可以稳定检查与重放。
此分工减少模型输出长度，也避免以自动修补掩盖模型对任务语义的误读。

## Consequences

- SPEC-018 的在线验收必须验证槽位到图的确定性结果和错误槽位的具名拒绝。
- 新语义提案本身不是 `built`，不能声明导航、抓取或 rollout 通过。
- 未来新增动作类型要先扩 SPEC、负例和构造器，不由模型自由添加谓词。
