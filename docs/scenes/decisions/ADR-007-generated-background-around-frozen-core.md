# ADR-007：冻结任务核心之外的程序化生成

- 状态：**accepted for implementation**（2026-09-22，用户授权按新 SPEC/PLAN 顺序执行），仅可选外围生成模式。
- 对应：SPEC-009。

## Context

ADR-002 将建筑交给 Infinigen、家具全部交给检索。用户现在要求更完整的 Infinigen 生成能力及光照。
若包含外围家具，必须明确修改该分工，不能通过 populate=True 暗中替换任务核心。

## Evidence

能力核对：pinned commit
`892947be71c4ff102c6a558d088ffe149561c11f` 将大型/中型/小型家具与 populate 分阶段。
RFW-W 当前关闭 populate，且现有导出只取建筑集合；来源、碰撞与 core 约束均需新的接线。

## Options

1. 只扩展建筑材质和光照，全部家具继续检索。
2. 建筑、可选外围家具及装饰由 Infinigen 生成；任务核心继续检索并冻结。
3. 全部家具和任务核心均改由 Infinigen 生成。

## Decision

拟采用 2 作为可选模式，默认兼容既有检索模式；该决策已获实施授权，当前代码尚未实现。
显式实体分配唯一 owner，任务依赖闭包属于 core；生成物必须通过保护区与通道验证。

## Rationale

外围生成能增加视觉多样性，同时保留已有核心资产、任务关系与验证链。选项 3 会改变产品基础，超出本次需求。

## Consequences

新增外围实体来源清单、碰撞与语义映射、拒绝池、有界预算；增加生成与材质导出成本，需实测。
静态程序化家具不获得可操作/关节认证。若最终只选建筑能力，SPEC-009 可保持 deferred，006–008 可独立完成。
