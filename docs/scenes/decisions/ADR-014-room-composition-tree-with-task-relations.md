# ADR-014：逐房生成树与跨房任务关系共用一份图

- 状态：**accepted**（2026-10-01，SPEC-019）。
- 范围：G1 的场景构成意图；G2 的几何求解另立 SPEC。

## Context

SPEC-017/018 能表达房间、门、资产角色和动作状态，却没有每房建筑及家具内容。后续建壳与摆放需要初始父子顺序；跨房门户和任务状态又不是一棵静态树能完整表达的。

## Evidence

- 本仓 `contracts/task_world_graph.py:15-38` 的 v1 节点没有地面、墙或干扰物策略；`contracts/state.py:436-445` 的旧生产 `SceneIR` 仍是单房。

## Options

1. 每房单独维护场景树，再用任务图引用它们：会有两份可编辑身份与版本账。
2. 把门连接、任务前后态也压进一棵树：无法自然表达共享门和物体跨房移动。
3. 在现有全屋图中加入初始生成树，保留关系边与动作状态序列（采用）。

## Decision

同一 `TaskWorldGraph` 增加可选的构成版本和建筑意图节点。`contains` 在构成版本下是单父、无环的**初始生成树**；门户仍用一个节点和两条 `connects` 边；任务位置仍由初态与步骤效果推导。资产类别、任务角色和 `core|optional` 优先级是不同字段。两房墙体先记 `wall_set` 意图，不伪造尚未求解的墙段。

## Rationale

树使逐房生成有明确顺序；其他边保留共享资源和任务关系。单图 ID 与内容哈希可使后续几何、资产和证据引用同一版本。可选干扰物可在缺资产或空间不足时被丢弃，不改变任务核心。

## Consequences

- 旧图不声明构成版本时仍能读取，但不能通过 SPEC-019 的完整房间检查。
- G2 须把 `wall_set` 展开为真实墙段、洞口和连通尺寸，并写回新图版本及测量证据。
- G3 须分别记可选候选的接受、拒绝与未放置；不得让可选物体成为任务必需物。
