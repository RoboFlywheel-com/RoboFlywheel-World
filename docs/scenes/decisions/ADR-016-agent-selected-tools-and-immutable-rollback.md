# ADR-016：Agent 选择受约束工具，回退产生新版本

- 状态：**accepted，首例动态选工具与限域回退验收通过**（2026-10-03）。
- 范围：跨房 Agent；旧单房 Driver 的 checkpoint 与修复梯子只作为可复用机制参考。

## Context

`SceneGenerationAgent.TOOL_ORDER` 目前固定 11 步，成功后提交 G2/G3 图版本；失败记录阶段和原因码，但没有基于当前状态选择下一工具、恢复旧检查点或定向重验的接口。用户要求 Agent 决定何时调用哪个工具，并允许回退和改动第一版核心图。

## Evidence

- `contracts/tool.py` 已有 `ToolRequest/ToolResult`、状态哈希、作用范围、具名失败和只读/写入边界。
- `TaskWorldGraph.revise()` 已建立父哈希和新修订号；`check_evidence()` 拒绝与当前图哈希不符的证据。
- 现有 G2/G3 编排器按硬编码顺序运行，没有统一的工具可用条件、效果注册表或模型选择回合。
- 旧单房 `orchestrator/driver.py` 有 checkpoint/失效机制，但其单房状态不能直接视作跨房图状态。

## Options

1. 把固定 11 步改成更长的固定列表。
2. 允许模型输出任意工具名、参数和图补丁。
3. 注册受约束的工具能力、前置条件和可写范围，由 Agent 在合法集合内选择；每次执行后重新计算可用工具；回退作为有证据的版本事务（拟采用）。

## Decision

采用 3。模型可基于**任务语义、图中已允许的摘要和具名失败码**提出下一工具、作用范围与原因；确定性调度器验证工具注册、前置条件、预算和版本后执行。模型不得伪造 `ToolResult`、直接写 `built` 或宣布验证通过。简单的必然依赖可由调度器执行，至少一个有多个合法选项的决策点必须由 Agent 实际选择，不能用固定顺序冒充自适应。

回退不覆盖旧图或旧目录。它从已保存的 checkpoint 和候选修订构造**新**图版本，记录回退来源、修改范围和原因；所有受影响证据失效并重验。保留用户硬约束、任务目标与稳定角色 ID；需要修改这些语义时按 SPEC-023 的受约束图编辑重新验证。

## Rationale

工具前置条件由代码控制，模型负责有语义意义的选择，可以避免它直接编造几何和成功证据。不可变版本让失败、回退与新尝试可独立复核；重验阻止旧图的成功证据被错误继承。

## Consequences

- SPEC-026 先验证 checkpoint、回退、作用范围与证据失效；SPEC-027 再验证工具注册、动态选择和预算。
- 模型调用继续遵循 AGENTS.md §5：显式外发许可、只发送任务语义与清洗后的失败摘要，不发送资产路径、日志、仓库文件或凭据。
- G4 机器人验证和 G5 的机器人失败后修复仍是独立关口，不因本次图/静态工具调度而声称完成。
