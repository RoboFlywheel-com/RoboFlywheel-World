# ADR-012：跨房路径从任务图约束全屋，单房 core-first 保留

- 状态：**accepted**（2026-09-30，产品方向由用户确定）
- 范围：新跨房长程任务路径；不追改既有单房 delivery 与验收事实。

## Context

当前任务场景目标 现在要求按指定机器人与任务编译可验证的评测场。
当前单房路径按 [ADR-001](ADR-001-room-plan-as-the-core-to-room-contract.md) 先解并冻结局部 core，
再拟合房间。跨房任务需要多个工作区、门与通道，还需要在机器人失败后改变某个工作区或门；
一个永久冻结的单房 core 无法承担全屋权威状态。

## Evidence

- `SceneSpec.room` 与 `SceneIR.room` 是单房语义；`RoomPlan.rooms` 虽为序列，
  当前 shell 转换仍拒绝多房。见 SPEC-017 的验收边界。
- 旧单房 core-first 的实测收益仍成立（office 杯子可用接近方向 2/24 → 19/24，
  见 ADR-001）；没有证据支持删除那条路径。

## Options

1. 把若干单房 `SceneIR` 拼接成整屋，任务关系事后补上。
2. 先生成房屋，再把任务与机器人塞进已有房间。
3. 先规划任务约束与全屋拓扑，再由局部 cell、户型、资产及机器人工具迭代落实（采用）。

## Decision

采用 3。第一工具 `plan_task_world_graph` 提出任务阶段、房间与共享开口、工作区、
资产角色和验证义务；它只产出**候选意图图**，不自报建成几何、资产可抓或机器人可行。
同一全屋图的稳定 ID 贯穿下游；意图、建成状态与证据分别存储。
验证失败由统筹 Agent 通过有范围的工具事务修复；旧证据按依赖失效并重测。
单房 `solve_cell` 可作为局部候选生成器；跨房路径不把其第一个结果冻结为全屋不可改的前提。
旧单房入口仍按 ADR-001 的已接受语义运行。

## Rationale

跨房成功取决于空间与任务的共同约束：门可通行、两端有停靠与操作区、目标资产可抓、
搬运期间状态保持、终态可判。先把这些要求连在同一图里，才能把失败定位到可修复的对象，
并比较修复前后是否真正改善。

## Consequences

- 建立 stdlib-only 全屋图契约和独立规划工具；二者分别验收，见 SPEC-017/018。
- 房间子图、时间线与资产清单是全屋图的视图，不另存一份可独立修改的事实。
- 旧 [ARCHITECTURE.md](../ARCHITECTURE.md) 仍描述生产系统；新路径只有实现与验收后才写入当前架构图。
- 后续户型、资产、机器人和 Agent 修复各自立 SPEC/PLAN，不在首个规划工具里隐式实现。
