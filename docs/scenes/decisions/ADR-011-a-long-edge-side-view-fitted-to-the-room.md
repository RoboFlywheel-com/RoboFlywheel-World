# ADR-011：交付的整屋视角改为"长边中心侧视"，并按房间自身取景

- 状态：**accepted for implementation**（2026-09-24，项目所有者指定方向并逐项确认，见文末留痕）。
- 对应：SPEC-015（本 ADR 是它的设计依据）；
  改写 `rfw_w.scenes.commands.generate` 的机位集，触及 SPEC-005
  与 SPEC-008 的取证面，但**不改**两者的 gate 与结论。
- 前序：[ADR-002](ADR-002-room-shell-from-infinigen.md)（外壳交给 Infinigen）、
  [ADR-005](ADR-005-room-shell-enters-the-render-path.md)（建成外壳进渲染路径）。
- 本文回答的问题：**交付的机位凭什么取景**——此前它只存在于 `run_m1_acceptance.py` 的代码注释里，
  没有任何 SPEC/ADR 认领过。

## Context

交付的七个视角（`overview_top` / `overview_corner` / `layout_top` / `room_eye_north` /
`room_eye_south` / `task_closeup` / `desk_workspace`）是在小房间上人工调出来的。其中：

- `overview_top` 在引用外壳时会**按足迹拟合**焦距（`min(14.0, 12.4*height/(1.1*span))`）；
- 另外六个的焦距是**写死的常数**（14 / 14 / 22 / 18 / 35 / 20 mm），与该房间多大无关。

SPEC-006 把房间尺寸变成可选的 `scale_class`（small 4–5×3–4、medium 6–7×5–6、large 8–10×6–8）之后，
这个缺陷第一次有了触发条件。

同一条命令、同一份 spec，只把房间换成 large：
`outputs/office_pick_cup/large_office_20260924_01`。

## Evidence

| 事实 | 实测 |
|---|---|
| 房间 | **67.62 m²**（U 形，外接 9.811 × 7.373 m，10 个开口），构建/几何/功能 gate **全过** |
| worker | **failed ×3**（638 s、`budget_exhausted`）：`ProtocolError: … layout_top / room_eye_south: an instance-id channel was saved without that camera's renderer id mapping` |
| 这两张图看到了什么 | `visible_instance_ids = [1]`（**只有外壳**）、`instance_id_map = {}` |
| 唯一活下来的机位 | `overview_top`：按足迹拟合出 **3.14 mm**，同一房间给出 **9/12** 实例映射 |
| 交付判级 | `achieved=draft`、`meets_request=false`、`failed=[backend.isaac.load/run/render]`、**`visual.critique` not_run** |
| 对照组（small，18.08 m²） | 同一条命令的 small 版：7 张图齐全、worker passed、critic 判过分 |

**机制**：`layout_top` 写死 14 mm、视高 ≈2.71 m，无论房间多大都只覆盖 **4.06 m**（按名义光圈）
或 **3.29 m**（按 `AGENTS.md` 记的 12.4 mm 有效光圈）——大房间要装 9.81 m，**永远装不下**。
`room_eye_south` 从房间中心外 1.9 m 拍中心，房间一放大，那段距离上什么也没有。
小房间能过是**巧合**（窄视场恰好还框得住家具），不是设计。

**另一条已记载的旧账，以及 2026-09-24 的实测结论**：`AGENTS.md` §"机器的行为"记着
"**渲染器的光圈不是代码假定的那个数**（有效垂直光圈 ≈12.4 mm，每个相机比焦距暗示的窄约 1.7×）……
**overview 两个机位是按它标定出来的，另外五个没有**"。这一次用
`rfw_w.scenes.visualization.measure_view_geometry`（§来源注记）从渲染自己的 depth 反推，结论是：

- **水平光圈就是声明的 20.955 mm，±3%**（small office 的四个独立视角：20.829 / 21.458 / 21.500 /
  20.745 mm，两两来自不同机位与不同 fit 模式；large office 的两个可用机位同为 x0.99 / x1.02）。
- **像素是方的（fy = fx）**，所以**声明里的 `vertical_aperture_mm`(15.2908) 被渲染器忽略**——
  实际竖光圈由画幅比推出 = 20.955 × 720/1280 = **11.79 mm**。历史上那个"12.4 mm"量到的正是这件事，
  只是当时把它记成了"每个相机窄 1.7×"。
- 因此**取景公式的正确形式是 `fx = f·W / a_h(声明)`、`fy = fx`**；本 ADR §Options 表里的焦距
  本身就是按声明水平光圈算的，**成立，不需要 ×0.84**（那条修正基于错误的 fill 模型，已撤回）。
  **但竖向视场比原先估计的窄**（原先按 15.29 竖光圈算）：小房间的竖向余量只剩 22.9° vs 需要 22.6°，
  所以 TASK 3 的取景必须**同时**满足"前一半足迹在画内"与"房间层高在画内"，再取较短的焦距。
- **新发现（不属于机位）**：渲染出的地面躺在 `room.floor_z_m` **上方 0.050–0.055 m**（五份数据一致）。
  工具现在把它当自由参数一起拟合，否则每个光圈读数都是有偏的，近俯视机位还会被误判成"画里没有地面"。
- **可辨识性**：光圈只通过相机系的竖向分量进入重建 z；近俯视机位的 lever = 0.007
  （wide/oblique 机位远大于 0.15），`layout_top` 因此在两个房间里读出 0.70 与 1.16 —— 工具按 lever
  具名拒绝，**近俯视机位不承担测光圈的职责**（取景由模型算，光圈由别处的实测背书）。

**附带的证据缺陷**：worker 失败路径重建 report 时不带 `openings_requested`/`openings_cut`
（`render_worker.py:1077-1097`），manifest 又从它推出 `door_cut`（`run_m1_acceptance.py:4190`），
于是这份交付**发布了一个它没测量过的房间属性**（`door_cut=false`）。

## Options

1. **维持写死焦距，把空视角改成致命错误。** 改动最小，失败信息更准；但取景仍然与房间无关，
   large/medium 档依旧拍不到，只是失败得更清楚。
2. **按外接框长边跨度拟合**（第一版原型）：眼位到对面墙的距离 d，半角 = atan((L/2)/d)。
   矩形房间正确；对 U/L 形房间，外接框的"长边中点"可能落在凹口外、远端跨度也不是 L。
3. **长边中心侧视 + 按房间自身足迹拟合（采纳）**：眼位取长边中点、向室内走 0.15 m（做墙距与
   在室内校验，非矩形房间沿法向搜索合法点）；注视对面长墙；镜头 = **仍能装下"房间前一半全部
   足迹顶点"的最长焦距**（6% 余量）。
4. **再加一个机位（8 个）。** 否决：critic 的图片 payload 已经出现过一次超时，
   加一张只会更糟；而且多出来的这张与 3 是同一个用途。

方案 3 在四个真实房间上算出来的取景（原型：

| 房间 | 面积 | d | 半角 | 反算焦距 | 前一半足迹 | 地板进画 | 竖向余量 |
|---|---|---|---|---|---|---|---|
| office small（矩形） | 18.08 m² | 3.49 m | 36.8° | 13.99 mm | 全在画内 | 51.5% | 28.7° vs 需 22.6° |
| office large（U） | 67.62 m² | 7.17 m | 51.6° | 8.31 mm | 全在画内 | 70.8% | 42.6° vs 需 11.5° |
| kitchen（L） | 22.74 m² | 4.36 m | 33.5° | 15.83 mm | 全在画内 | 56.3% | 25.8° vs 需 18.8° |
| bedroom（L） | 16.50 m² | 3.47 m | 36.0° | 14.42 mm | 全在画内 | 54.3° vs 需 22.6° |

（"地板进画"是**诊断数字**，不是阈值：贴墙站位的相机必然看不到自己脚下的那一带；
本 ADR 不冻结它的下限，等 TASK 1 的测量工具在多房间上跑出分布再定。）

**表中的焦距按声明的水平光圈（20.955 mm）算出，而实测证实渲染器用的正是这个值**（见 Evidence），
所以表中的数字成立。**但竖向要单独校核**：像素是方的（fy = fx），竖向半角比按声明竖光圈算的更小，
小房间的余量只剩 0.3°——TASK 3 必须同时满足"前一半足迹"与"房间层高"，取两者中较短的焦距。

## Decision

1. **机位数固定为 7**；`room_eye_south` 由 **`overview_side`（长边中心侧视）** 替换。
2. **取景规则**：眼位 = 长边中点向室内 0.15 m（在室内 + 墙距 ≥0.15 m 校验，非矩形房间沿法向
   逐步搜索第一个合法点，挪动了多少要记录）；注视对面长墙的同高度点；
   镜头 = 仍能装下**房间前一半全部足迹顶点**的最长焦距（6% 余量）。
3. **该视角的义务是几何的、可在取证前判定的**："房间前一半的足迹顶点全部在画内"。
   预检不通过（找不到合法眼位或算不出覆盖）→ **具名缺口、不渲染**。
4. 渲染回来仍然空（拍到 0 个家具实例）→ **具名缺口 `VIEW_EMPTY(camera_id)`，交付继续**，
   不让整趟作废；但交付必须把这张图是空的这件事写进自己的证据。
5. **光圈以"钉死 + 每跑自证"为准**：worker 把请求声明的 aperture 写进 USD camera，
   并且**每次运行都用该次渲染的 depth 反证**有效光圈；与声明不一致 →
   `CAMERA_APERTURE_MISMATCH(declared,effective)`。取景公式的前提必须被证明，而不是被假定。
   **2026-09-24 实测补充**：这条现在有了依据与边界——水平光圈实测等于声明值（±3%），
   而**声明的竖光圈被忽略、竖向由画幅比推出**；所以自证要核的是这条模型（fx = f·W/a_h、fy = fx），
   并且只由**有辨识力**的机位（lever ≥ 0.15）来核。
6. **有效光圈的测量工具先立起来**（SPEC-015 TASK 1），带合成数据的自检（已知光圈能否被反推回来）。
   在此之前，本 ADR 引用的任何"有效光圈"数字都只是历史测量，不参与判定。
7. **失败路径不得发布未测量字段**：失败 report 不带 `openings_*`/`lighting`/`shell_reference`，
   manifest 的 `door_cut` 在失败时为 `null` + 具名理由。

## Rationale

- **为什么是"长边中心侧视"而不是俯视。** 俯视（`layout_top`）要从上面同时装下房间与家具，
  视场必须覆盖整个足迹，房间一大就得极广角、畸变重；侧视把"看全房间"变成一条**一维**要求
  （长边跨度），镜头只需要 14–16 mm，构图更像一张立面照，用户在图上第一次能真正看到房间。
- **为什么义务写成"前一半足迹顶点在画内"。** 它是几何事实、可在**渲染前**判定、无需发明阈值，
  而且正好对应"这张图要给人看的是整间房"这个用途。相邻的"地板进画比例"依赖站位，只能当诊断量。
- **为什么空视角不致命。** critic 少一张图仍然能判（其余六张照常）；而一次取景失误让整趟
  20 分钟 + critic 费用的交付作废，代价与收益不成比例。预检把"空图"压到罕见，
  具名缺口保证它不会被当成没事。
- **为什么光圈必须每跑自证。** 取景公式里光圈与焦距是乘积关系：光圈错 20%，视场就错 20%，
  远端角点照样掉出画外——等于把今天这个 bug 换个形式复发。这次实测把"哪个光圈生效"量清楚了
  （水平=声明、竖向由画幅比推出），也正因为它**不是**代码里那两个数，自证才是设计的一部分：
  今天是 11.79 mm 对 15.29 mm，明天上游改了拟合方式就又是另一个数。
- **为什么不动 gate。** 本 ADR 只改"拍什么、怎么拍、拍不到怎么记账"，不碰任何 gate 的判据；
  SPEC-005/008 的结论与阈值都不受影响。

## Consequences

- **好**：整屋视角随房间尺寸正确取景；large/medium 档不再因为机位而失败；
  每张图的义务与覆盖成为交付里可读的证据；失败不再由一个空图引发三连红。
- **代价**：`room_eye_south` 这个机位名消失（它唯一 `save_depth=false` 的特殊性一并消失），
  引用它的报告/工具要跟着改；取景公式与光圈核对要多写单测；
  worker report 与交付多出 `view_coverage` 一类字段（schema 要同步）。
- **已知瑕疵（如实记录，不隐藏）**：U 形房间的侧视会**穿过凹口看到室外**（原型图里可见）。
  这是"从长边中点直看对面"的几何后果；本 ADR 不回避它，也不因此改成曲线取景。
  若日后要处理，属于新的一条决定。
- **不解决的**：大房间显得空（家具密度，属 SPEC-009/010）、材质与光照（007/008）、
  论文图版（012/013/014）。
